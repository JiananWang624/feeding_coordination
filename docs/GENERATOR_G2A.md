# G2A: endpoint-constrained transfer trajectories

G2A is an offline transfer-only comparison. It retains each frozen G0 Contextual ProMP trajectory as the nominal path and adds a late quintic position correction toward a provisional virtual goal. It does not change G0, G1, StrongLocal, Exact-SEW, withdrawal, or robot joint trajectories.

## Endpoint semantics

The upstream labeled-data extractor constructs `target_x/y/z` once per bite from the *recorded transfer final frame*: `Hand_final + 80 mm * ForkMinusY_final`. Phase 1.5 validates the tracked fork-rigid-body origin against `Hand + 100 mm * ForkPlusY`. In project B coordinates, this yields the recorded relationship

```text
mouth_proxy_B ≈ measured_transfer_final_fork_origin_B
                - 0.18 m * measured_transfer_final_fork_R_B[:, 1]
```

`target_x/y/z` is a position-only point in Motive Global coordinates (millimetres before Phase 1.5's transform). It is held constant across transfer and withdrawal for that bite. It is neither an independently sensed mouth pose nor a calibrated mouth-to-fork rigid transform. The 0.18 m relation comes from explicit directed offsets, not a fitted scalar distance. The source is `F:/code/optitrack_data_preprecessing/extract_labeled_trajectories.py`.

For this *provisional offline experiment*, the query-side G0 `mouth_proxy_B` is accepted as context at the user's direction. The virtual position goal is constructed without reading the measured final fork pose:

```text
virtual_transfer_goal_B = mouth_proxy_B
                          + 0.18 m * nominal_final_fork_R_B[:, 1]
```

The nominal final orientation is generated by frozen G0, not copied from the held-out measurement. Because `mouth_proxy_B` was originally computed from that held-out transfer final frame, however, this evaluation contains **indirect future-endpoint information**. It must not be described as an independent-target or deployment-valid test. No trustworthy query-side terminal orientation is available, so G2A constrains terminal **position only** and leaves the entire orientation path nominal.

The persisted metadata declares `physical_tool_calibration_validated = false`, `physical_mouth_pose_validated = false`, `virtual_endpoint_constraint = true`, and `withdrawal_endpoint_optimization_deferred = true`.

## Method and evaluation

For a selected start phase `s_a` in `{0.50, 0.65, 0.80}`, the constrained path equals the frozen nominal path before `s_a`. Thereafter it adds `h(u) * (virtual_goal - nominal_endpoint)`, where `u = (s-s_a)/(1-s_a)` and `h(u) = 10u^3 - 15u^4 + 6u^5`. The first and second derivatives of this correction vanish at both ends. The resulting last position must equal the virtual goal to floating-point tolerance.

Each of the seven held-out take folds selects `s_a` using inner leave-one-training-take-out, bite-balanced full-trajectory position RMS. No held-out test trajectory is consulted for selection. Later `s_a` wins an exact tie. The nominal path is reconstructed with the G0-selected fold alpha and checked against the saved G0 artifact before correction.

Reported errors serve distinct purposes:

- **Virtual-goal error** is the numerical endpoint-contract check and should be zero.
- **Measured-demo endpoint and trajectory errors** compare against the held-out fork-rigid-body trajectory *after* generation. These are diagnostic, never inputs to the virtual goal.
- **Adaptation magnitude and phase derivatives** measure geometric deformation, not physical Gen3 speed, acceleration, safety, or executability.

G2A is not fork-tip calibration, mouth sensing, physical endpoint validation, collision checking, retiming, robot IK, or G1 robot realization. Even an exact virtual-goal endpoint does not establish that a real utensil reaches a real mouth.
